# С чего я начинаю разбор

Я открываю этот каталог отдельной папкой VS Code или через общий учебный workspace.
Расширения редактора не обязательны: запуск и проверки доступны из терминала.
Я читаю README и выполняю demo, затем иду по карте ниже.

| Файл | Что я здесь объясняю | Где я меняю поведение |
| --- | --- | --- |
| `cmd/windowlab/main.go` | Мои demo, параметры CLI и безопасный новый выход | Константа demo и DefaultConfig, оформление ответа |
| `internal/windowing/windowing.go` | Контракт → seen → прошлый watermark → окно → новый watermark → trace | parseEvent, Run, Config.Validate |
| `internal/windowing/windowing_test.go` | Границы времени, ID, чтение и эталонные суммы | Новые граничные примеры до изменения алгоритма |
| `cmd/windowlab/main_test.go` | Полный demo, повтор и сохранность файлов | Сценарии команд и ожидаемые бизнес-числа |
| `scripts/ci.py` | Мой gate с собранным бинарным CLI и двумя ZIP | Дополнительный пользовательский сценарий |
| `scripts/package_release.py` | Allowlist, privacy scan, Git root, повторяемый source ZIP | Только осознанное изменение поставки |
| `scripts/publish_release.py` | Guard main, неизменяемый тег, draft → assets → publish | Версию я меняю отдельно в VERSION |
| `PUBLIC_FILES.txt` | Что именно я публикую | Каждый новый исходный файл добавляю явно |
| `DEPENDENCIES.json` / `TECHNOLOGIES.md` | Реальные версии и отсутствие внешних Go-модулей | Обновление версий я отделяю от бизнес-правил |
| `.github/workflows/check.yml` | Две ОС и зависимый от них release job | Permissions write я оставляю только выпуску |
| `.vscode/tasks.json` | Мои три задачи редактора | Для повторов я выбираю новые имена файлов |
| `NOTES.md` | Решения, путь строк, ограничения, 5 заданий с ответами | Здесь я сверяю смысл своих изменений |

Я ставлю точку остановки перед сравнением `end` с `out.Watermark`, затем смотрю
строки 5, 6, 9 и 10 demo. На строке 5 я вижу 10:06, на строке 6 — отказ старого
окна; на строке 9 — 10:10, на строке 10 — точную границу end==watermark.
Я не нуждаюсь в отладчике, чтобы повторить это: те же данные есть в `trace` JSON.

Я предпочёл явные структуры вместо map[string]any, чтобы ошибка типа суммы
не превратилась в float64. Я не удаляю seen после закрытия окна: иначе поздний
повтор стал бы новым событием. За это я плачу памятью до max-rows. Я не называю
буферизованный вход полностью потоковой системой: итоговые группы и трассу держу
в памяти. Другие аргументы и упражнения я разбираю в NOTES.
